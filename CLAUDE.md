# Parabolica Race Engine

Formula 1 race simulation, building toward Commissioner Mode (wall-clock roguelite leagues).
Player betting was retired in June 2026 (git history has it); odds math survives in betting/utils
for the future NPC-crowd system (BetLab was removed Oct 2026; git history has it).

## Project Location
`/Users/pax/parabolica`

## Structure
- `src/` - All source code
  - `App.tsx` - Screen router: main menu, quick race, founding, league, compendium
  - `WatchMode.tsx` - Live race screen (track/detail views, finish modal)
  - `racecontrol/` - Race Control, the lab (unlocked from the menu): `runner.ts` is the ONE way a lab race is built (createLeague + prepareScheduledRace = live parity, fully seeded); `calibrate.ts` measures every genesis tag solo; `physics.ts` measures what the rules produce (mechanics-probe metrics); `knobs.ts` is the simVars registry; `labRunner.ts` runs jobs in a worker or on the main thread; `notebook.ts` keeps presets + runs in localStorage and sends batches to the shared ledger (`public/ledger/*`, fed by `ledger` issues via `.github/workflows/ledger.yml` + `scripts/ledger-ingest.mjs`) (Quick Race → Run Setup → Lab preset races under one via `applyLabPreset`); `RaceControl.tsx` hosts Tag calibration, Physics calibration, Notebook, Method
  - `fantasy/` - Fantasy teams: `types.ts` (config, snake order, F1-table scoring), `DraftPanel.tsx` (teams + obfuscated draft), `FantasyStandings.tsx`; config lives in `LeagueSetupConfig.fantasy` (travels with a published league); timing tower tints drafted rows (docs/FANTASY.md)
  - `simlab/types.ts` - `SimVariables` + `CANON_VARIABLES` (the engine's tuning surface; the old Sim Lab UI was folded into Race Control → Physics)
  - `data/tagCalibration.json` - GENERATED by `npm run calibrate`; a deck test fails when a genesis tag is missing, changed since measured, or out of band
  - `betting/utils.ts` - Pure odds/rating utilities (kept for NPC crowds later)
  - `feed/commentary.ts` - Race feed persona/commentary engine
  - `RaceEngine.ts` - Core race simulation engine (seedable: setSeed / runHeadless(seed))
  - `engine/rng.ts` - Seeded RNG (mulberry32, deriveSeed, shuffle) — determinism foundation
  - `storage/persistence.ts` - Versioned localStorage league save
  - `league/` - Commissioner Mode: seed → universe, wall-clock settle loop, interventions
    - `remote.ts` - the league server client: publish, open by code / `#league=CODE`, 30s sync, digest posting (docs/LEAGUE_SERVER.md)
    - `gods.ts` - Appetite gods — PARKED (founding no longer asks; leagues found under GODS[0] silently)
    - `ui/` - FoundingScreen, LeagueScreen (check-in reel, countdown, standings, chronicle)
    - `devConsole.ts` - window.league console (dev builds only)
- `server/` - The league service: Cloudflare Worker + Durable Object (`wrangler.toml`, `src/index.ts`); deployed by `.github/workflows/deploy-api.yml`; `cd server && npx wrangler dev --local` to run it locally
- `dist/` - Production build output
- `public/` - Static assets

## Commands
- `npm run dev` - Start dev server (localhost:5173)
- `npm run build` - Production build
- `npm test` - Run vitest suite (engine determinism, league invariants, persistence)
- `npm run glossary` - Regenerate docs/GLOSSARY.md from the data modules (a test fails when it is stale)
- `npm run calibrate` - Re-measure every genesis tag → src/data/tagCalibration.json (~15 min; `-- 50 <tagId>` for a quick unwritten read)
- `npm run lab -- <seed> <races> all [cards…]` - Replay a Race Control batch in the terminal and print its fingerprint
- GitHub: `gh api` REST only (GraphQL is blocked in sessions) — see the `write-issue` and `ship-pr` skills

## How we work
- **Read first:** the newest `docs/HANDOFF_*.md` (how the pieces fit, traps, open work).
- **Skills (`.claude/skills/`)** hold the procedures: `write-issue` (issue shape, triage, `ready`), `ship-pr` (build → test → PR → merge rules), `republish-preview`, `balance-read`, `season-report`.
- **Asana is the task system. Every thread, every crew member.** Project ["🏁 Parabolica"](https://app.asana.com/1/1219276824761487/project/1219276019625158) (workspace "My workspace"). Look there first for what to do; don't track work anywhere else (no TODO docs, no GitHub milestones/projects).
  - **Sections = releases:** `🇧🇪 v0.5 Spa` (**the current release: the only thing being worked on**), `🇮🇹 v0.6 Monza`, `🇯🇵 v0.7 Suzuka`, `📥 Queued` (committed, unslotted), `🧊 Icebox` (maybe / needs Pax). Target date is in the section name.
  - **Only the current release gets Crew + due dates.** Everything past it stays unassigned and undated until Pit pulls it into a release.
  - **Fields:** **Crew** (who + which model; `Pax` = needs his call) and **due date**. Titles are plain, no issue numbers, no status prefixes.
  - **GitHub issues are the build spec**, linked in the task description. Every new issue gets an Asana task; every Asana task that needs code has an issue.
  - **When work ships:** tick the Asana task done. When starting: note it in the task. If the Asana connector isn't available in your chat, say exactly what to change in your final message so Pit can apply it.
- **`ready` label is the handoff.** Scope an issue until it can be built without guessing, then label it `ready`. Build only `ready` issues (or one Pax names). Out-of-scope finds become new issues, not extra code.
- **Planning sessions** (issues, scoping, docs) don't edit `src/`, `server/`, `scripts/` or tests. **Build sessions** do one issue per branch/PR.
- **Talking to Pax:** Smart Brevity — TL;DR first, bullets, bold the key bit, plain words. Anchor changes to where he sees them (screen → button). Link issues with titles, never bare numbers. Questions as multiple choice (A / B / C, pick marked). Story and theme are Pax's — capture, don't invent canon.
- **Done** = merged, live on playparabolica.com, and (for UI) checked in the browser.

- **Routing rule (Pit):** Fable time is scarce, so only tasks that need it go to Apex. Wrench tasks are scoped so tightly a small model can't go wrong (exact files, exact change, a check to run). Anything risky gets split out into its own Apex task.

- **Stay in your lane:** if a task turns out bigger than its crew, stop, comment why on the issue, and hand it back to Pit to re-route.
